# Gate 8 Slice D — Prospective Integration and Decision

## Implemented boundary

Slice D adds a prospective Integration and Decision capability on top of accepted Slices A–C. The
natural `Integrate Value and Risk` command consumes one exact, current Gate-6 relied chain from each
independent lane. Each chain retains its Assessment, Readiness, Adequacy, Reliance, and exact
information/Applicability Versions. There is no legacy Fitness/Acceptance/Selection fallback,
cross-lane substitution, score, netting, or incidental winner.

The Decision path keeps proposal, authorization, and unchanged-Decision confirmation as distinct
governed acts. Proposal retains the exact Integration and underlying immutable lane basis.
Authorization creates an authorized successor Decision Version and a separate exact authorization
fact. Confirmation binds an unchanged authorized Decision; it does not amend it. Explicit successor
proposals preserve predecessor history and require a new current Integration basis.

Every command revalidates the prospective OPEN Case, exact governing Configuration/context, exact
current relied chain, source access, Responsibility/assignment, substantive authority where
required, and expected predecessor inside the outer semantic transaction. Exact replay returns the
original outcome; mismatched reuse, stale basis, authority vacancy/conflict, hidden source, or
concurrent predecessor change produces zero semantic mutation.

## Persistence and migration

Migration `0013_gate8_integration_decision_basis` is additive and introduces append-only
prospective Integration, Decision, authorization, and confirmation projections. No legacy row is
backfilled or reinterpreted. Downgrade is prohibited after any Slice-D fact exists.

Historical Integration and Decision Versions retain exact then-bound bases even after later lane,
Configuration, Integration, or Decision successors. Current selectors return one, absence, or
unresolved conflict without recency, favorability, role, magnitude, or row-order selection.

## Deliberate exclusions

This slice does not implement continuing review/timing, quantitative claims or comparison,
complete then-versus-now UI, Harborlight runtime validation, scheduler/notifications, multi-user
deployment, analytics/Observation/telemetry, or a release decision.
