# PAIM Gate-7 Implementation Slice Plan

## Sequencing rule

Implement dependency-ordered vertical slices that produce a coherent practitioner behavior as soon
as the required semantic foundation exists. Each slice includes domain values, ports, persistence,
application commands/queries, thin practitioner expression where authorized, migration evidence,
and hard oracles. No slice may defer access, replay, history, or failure behavior to a cleanup pass.

This plan authorizes no slice. Each requires its own bounded issue, draft PR, independent review,
merge, clean-main checkpoint, and explicit instruction to continue.

## Dependency order

```text
A common semantics + Responsibility/Work
    -> B continuing Case + core attention
        -> C Value/Risk Finish -> Adequacy -> Reliance
            -> D Integration/Decision prospective consumption
                -> E continuing review/timing/focused refresh
                    -> F quantitative claims/comparison
                        -> G then-versus-now reconstruction
                            -> H integrated user-centric Harborlight validation
```

Slice F may develop its pure claim types after A, but its practitioner comparison cannot exit
before E. Slice G may build query primitives earlier but cannot claim completeness before D–F.

## Slice A — common semantics, Responsibility, and Work foundation

**Entry:** accepted Gate-7 package; current `0008` head; common-integrity, Responsibility, and Work
hard oracles fixed.

**Implement:** semantic contracts, exact context sets, Version metadata, cutover declarations,
prospective practical roles, Responsibility/Assignment Basis/assignment, durable Work,
result/return, stale no-retarget, explicit legacy Role adapter, and composed transaction support.

**User-visible vertical proof:** from one new disposable prospective Case context, an authorized
participant resolves a vacancy, assigns an exact Responsibility, hands off Work, records the owning
governed result, and returns without exposing IDs or Work/result mechanics.

**Exit tests:** fresh/`0008` upgrade; canonicalization permutations/duplicates; semantic contract
digest; one/vacancy/conflict; delegation/reassignment history; same Actor/multiple Responsibilities;
access/non-disclosure; stale Work; result substitution negative; combined result/return rollback;
replay/mismatch; dual-time reconstruction; untouched legacy digest.

## Slice B — continuing Case and core Home/Case/Task composition

**Entry:** A accepted; exact Responsibility and context ports available.

**Implement:** prospective `OPEN`/`CLOSED`/`SUPERSEDED`, Continuity Determination, closure/reopen/
supersede commands, Configuration continuity guards, Home/Case/Task composition over prospective
sources, and legacy lifecycle adapter.

**User-visible vertical proof:** create/open a bounded proposed use in ordinary language, see exact
attention at Home/Case/task, reject closure with outstanding obligations, and open a materially
different use as a new Case.

**Exit tests:** same/new Case; one governing Configuration; concurrent subordinate state; closure
guard matrix; discontinued operation stays open; reopen; terminal superseded predecessor; no new
work; access-before-composition; hidden-count/conflict non-leakage; no universal phase; atomic zero
mutation; legacy history unchanged.

## Slice C — independent Value/Risk Finish, Adequacy, and Reliance

**Entry:** A/B accepted; prospective Case, exact context, Responsibility, Work, information, and
Applicability ports available.

**Implement:** candidate finalization plus Readiness, neutral Adequacy, Reliance, candidate
dispositions, combined Complete review transaction, separate-Actor path, explicit legacy
Fitness/Selection adapters, and lane practitioner views.

**User-visible vertical proof:** independently finish Value and Risk assessments, resolve a
contextual information prerequisite, judge adequacy neutrally, and complete each review through one
natural action when its combined guards apply.

**Exit tests:** Value/Risk symmetry and independence; favorable/unfavorable/uncertain adequate;
not-adequate/indeterminate causes; Applicability separation; one/multiple candidates; no automatic
winner; same/different Actor; atomic two-fact rollback; successor-on-edit; reuse; stale context;
access; exact history; legacy no reinterpretation.

## Slice D — prospective Integration and natural Decision actions

**Entry:** C accepted with exact relied chain selector; existing Integration/Boundary/Decision and
Authorization Basis services passing full regression.

**Implement:** prospective Integration basis links, current-chain oracle, propose/authorize/confirm/
successor command mapping, ordinary failure explanations, and Decision/current-position reads.

**User-visible vertical proof:** integrate one exact relied Value and Risk chain, compare alternatives,
propose, separately authorize, and later confirm or replace the Decision without selecting Versions
manually.

**Exit tests:** exact chain completeness; mixed-era rejection; lane change invalidates old chain;
zero mutation on stale basis; proposal/authorization separation; exact authority; predecessor
history; Confirmation versus successor exclusivity; no score/winner; access non-leakage.

## Slice E — continuing review, timing, and focused refresh

**Entry:** B/D accepted; Responsibility/Work, current Decision, Trigger/Reassessment, and exact lane
currentness ports available.

**Implement:** Planned Review Point, Required Review Constraint/intersection, Review Episode,
event-before-plan, arrival attention, focused affected-basis routing, carry-forward, completion,
optional separately valid next-point transaction, and scheduled-like legacy adapter.

**User-visible vertical proof:** set one next point, see a separate governing deadline, begin review
from an earlier event, refresh one lane, carry the other exact lane under its guards, and confirm or
change the Decision.

**Exit tests:** point one/absence/conflict; required-window intersection/empty conflict; move plan
within/outside authority; date arrival creates attention only; no automatic Trigger/Reassessment;
event provenance; one-lane refresh; no copying; no full-Reassessment inference; completion outcome;
combined next-point rollback; dual time; access; legacy isolation.

## Slice F — optional quantitative claim capture and comparison

**Entry:** C accepted; E comparison context and information/Applicability ports available.

**Implement:** stable typed Quantitative Claim family, optional context-sensitive capture,
comparability service, Value/Risk independent presentation, and expected-versus-observed read.

**User-visible vertical proof:** record Harborlight 20–35% `ESTIMATE_EXPECTATION`, later 24%
`OBSERVED_RESULT`, and a distinct source-linkage result; compare only the first pair when exact
guards pass and explain non-comparability naturally.

**Exit tests:** all six claim types; qualitative/no-number legitimacy; false precision/missing
material context; type separation; exact comparable/non-comparable contexts; no causality,
materiality, priority, Decision-error, ROI, probability-times-impact, net score, ranking, or
cross-lane inference; later knowledge never rewrites earlier claim.

## Slice G — then-versus-now reconstruction and emergent audit

**Entry:** A–F accepted; every included family exposes contract-aware dual-time query ports and
access filters.

**Implement:** Decision-bound source manifest, Decision-time effective/known query, separate current
manifest, practitioner then/now composition, progressive provenance, and cross-era adapters.

**User-visible vertical proof:** an authorized reader asks what Harborlight knew when it decided and
sees a separate current position, without later-fact contamination or assembling a report.

**Exit tests:** effective/known boundary permutations; same recorded/later effective facts;
Decision-bound exact Versions; semantic-era adapter provenance; hidden source/count/conflict
non-leakage; no master summary record; decision-quality/outcome-quality separation; deterministic
replay/source digest.

## Slice H — integrated user-centric expression and Harborlight runtime validation

**Entry:** A–G independently accepted; fresh prospective fixture authorization; no mutation of
historical Harborlight environments; the
[Practitioner UI Contract v1.0](../../design/practitioner-ux/PAIM_PRACTITIONER_UI_CONTRACT_V1.md)
is the controlling presentation and interaction contract.

**Implement:** only the coherent browser expression and bounded integration wiring needed for the
accepted journey and UI contract. Do not add UX-4/M1D scope by label; scope follows accepted
commands and must preserve their exact semantic boundaries.

**User-visible proof:** create a fresh disposable prospective Harborlight Scenario-A journey and run
the Gate-7 acceptance criteria with owner/practitioner review. Technical terms remain progressive
disclosure; ordinary work generates exact history.

**Exit tests:** full Gates 1–6 matrix; all slice regressions; browser accessibility/security;
restart/session-change handoff; stale/tampered context; one-person and split-person paths; complete
non-mutating legacy reconstruction; practitioner burden/leakage confirmation. Only this separately
authorized slice may run the new Harborlight runtime study.

## Release and deployment boundary

No slice changes the v0.1.0 tag or claim. A later release gate must aggregate migration, security,
resource, operator-documentation, full regression, longitudinal, and human evidence. Future
organization-local deployment remains a separate architecture/security gate after the local
prospective model is proven.
